## Soodles code-intel boundary: real parser, narrow scope

- Native Soodles `.agents/skills/code-intel/SKILL.md` and `code_intel.py` index **Python declarations only**. The existing `soodles_code_intel_inspect` (stale/ready/refused and original `refresh` next) must be used when an eligible native Soodles Python consumer requires structural facts. It does not provide a complete JS/TS call graph and is not available merely because a GitHub repo has a copy of its source.
- For this selected JavaScript/React consumer, `apps/loop-workbench/scripts/aifs-code-intel.mjs` uses the actual TypeScript compiler AST on **pinned source JS and chosen TSX consumer**. It checks real Git blob bytes, recognized `LF.register` keys, `window.LF`, `window.mountLessonFigures` and the matching script order. It outputs `ready` or explicit `refused`, annotated lexical declarations and source digests. It never invents an unobserved dynamic dependency/edge or native response. A schema/static search alone would not fulfill AST inspection.
- Reuse the same Soodles code-intel **method** for other chosen sources: first identify repository and exact Revision → select actual files by Consumer → choose a language-appropriate AST/structure parser (Python `ast`; JS/TS TypeScript AST; HTML DOM/tree; Markdown AST/fences; JSON/YAML structural tree) → list imports, registered IDs, functions, event listeners, side effects, dependency closure and original copyable bytes → reject stale/index drift → only then choose `vendor`, `wrap`, `extract` or `reference-only`. Do not run whole-project AST scans or install a graph server by default.
- A source's Repo README, its Website appearance, and its Git tree listing are **not** AST readback. When a required source cannot be parsed accurately, remain `UNKNOWN` and inspect another known-good candidate. This note does not claim SeeCode or OMM was newly reindexed with the AIFS parser.

## Rights, risks, migration evidence

- The AIFS software repo is MIT, which permits copied modules with attribution and retained LICENSE; individual course content, trademarks, videos, fonts and other third-party assets require separate rights. The copied files are the exact original modules; only the iframe document and host route are authored as new code.
- Browser-sandbox and CSP do not prove immunity to every attack: negative network/unsafe-origin/credential controls and actual Browser E2E are needed. Programmatic interaction tests prove math-widget DOM recomputation only, not correct learning outcomes or task acceptance.
- Require **actual AST + byte readback** before migration, and **actual browser rendering + input→output** after. Preserve negative tests for bad source digest, syntax error, missing symbols, escaping/cross-origin and non-public data. An empty manifest or a build success does not prove original author review.

Added code is only a finite scope AST/source contract, HTML frame and React view. Do not claim quantified saved person-hours or performance gain without an experimental baseline.
