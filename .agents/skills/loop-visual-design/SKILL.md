# Loop Visual Design Router

The canonical UI rendering and evidence validation live in Noodle/Soodles. This
skill is not an Agent scheduler, data reducer, source author or deployment owner.

Read design/visual-skills.lock.json and docs/loop-workbench-tanstack-start.md.
For repository-local installation, run:
python3 scripts/install_loop_visual_skills.py --dry-run
python3 scripts/install_loop_visual_skills.py

Select exactly the skills needed for the design decision:
- Taste (taste-skill): public narrative and showcase surfaces only; it says it is
  NOT designed for dashboard/app-screen workflows.
- Anatomy: hand-authored/pinned source-bound isometric SVG machine explanatory
  figures. Geometric projection never creates an execution event or reward.
- Impeccable: operational UI information hierarchy, a11y, responsive audit.
  Its executable launcher and optional downloads require separate source review.
- Emil: emil-design-eng plus review-animations and animation-performance for
  state-change clarity, keyboard interactions, reduced-motion and visual polish.

Existing build-review-interface remains the trace annotation methodology.
It is not evidence that an upstream design skill has actually run.

Execution states and colors are projected only from the original v2 DAG.
One visible node must map to one original node/object identity. Hover and
selection may read public source artifacts but never invoke a port or Owner next.
Current FAIL remains visible after a later PASS, UNKNOWN is not an empty success.
Honor the original reviewed disclosure boundary: do not read private Host traces
or post local artifacts to the cloud.

For frontend changes, test graph/data projections independently of appearance,
then run browser screenshots and keyboard/reduced-motion controls in the selected
host. Record installed skill version, actual invocation and screenshots, not just
a declaration that the skill existed.
