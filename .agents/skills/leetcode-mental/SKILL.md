# ALG-LeetCode Mental Simulator v4.0

## Entry and applicability

Select this Skill when the original task requests **a LeetCode problem, an algorithmic coding interview, or an algorithm-specific Zero Context tutorial** with v4-style reconstruction. The registered [medium-writing](../medium-writing/SKILL.md) remains the article writer/CLI owner. For ordinary v4 practice this Skill produces **source-validated algorithmic analysis**, not English-acquisition curriculum, Passive/Active classification, Four-Pass technique routing, a second Writer, a Stage or learner scores. When a user explicitly requests a complete Medium article, select [the complete-article content profile](references/article-content-profile.md): this Skill owns the full semantic article and the reviewed English-to-zh-TW content, while medium-writing remains the formatter/CLI owner. The two profiles do not replace one another.

Read the [full operational v4 contract](references/v4-contract.md) for ordinary v4 teaching, or the [complete-article content profile](references/article-content-profile.md) for a publishable Medium narrative. Read the [article style/source boundary](references/medium-reference.md) when a Medium-style example or granular explanation is requested. To see one complete adapted output, read [LeetCode 49 Group Anagrams example](../../../examples/leetcode-49-group-anagrams-zero-context.md) and its [replayable Python reference](../../../examples/leetcode-49-group-anagrams.py). The example is a *reference*; do not copy its state, invariant, number of loops or complexities into different problems.

For the complete article, first use its [article construction method](references/article-construction.md)
to derive the explanation from the selected problem, even without an exemplar.
Then apply the profile's [reader prerequisites and explanatory
steps](references/article-content-profile.md#reader-prerequisites-and-explanatory-steps).
Coverage of topic names is not coverage of the steps a novice reader needs to reconstruct
the mechanism. Preserve user-requested explanations when selecting equivalent code and
when reviewing sloptrim deletions.

## Keep writing routes separate

- **LeetCode algorithmic reasoning:** validate contract, select actual decisions and an equivalence property distinct from the loop invariant, produce five concise algorithm-memory anchors for the v4 profile, runtime movie, Python reference code, proof, complexity, first counterexample and transfer. Do not create lexical plans or learner pass progression here.
- **Ordinary FULL_SINGLE_TURN v4 teaching:** This Skill supplies technical analysis and the selected same-response Oracle; [medium-writing](../medium-writing/SKILL.md) remains the writer in the historical composed route, and [alg-four](../alg-four/SKILL.md) owns independent English learning. Do not treat the printable Oracle as native CEFR practice.
- **Complete Medium article profile:** This Skill alone writes and semantically approves the **entire** English article, runs/reviews upstream sloptrim when available, translates/reviews the **entire** zh-TW edition with exact English terms, and supplies dynamic figure specs/captions/alt text. [medium-writing](../medium-writing/SKILL.md) exclusively formats, submits and assembles approved words; it does not rewrite, summarize or cut any article facts. Four-Pass exercises do not become mandatory duplicated Medium headings.
- **General engineering/More Route article:** use the transferable [invariant-centered Zero Context lens](references/v4-contract.md#transferable-zero-context-lens), **not** mandatory five anchors, Python code, exact 14 sections, or a LeetCode-specific proof. Its actual Reader Decision Points come from the chosen Domain and evidence.
- **CEFR ALG Four-Pass frozen lesson:** [alg-four](../alg-four/SKILL.md) is the new English-acquisition lesson owner. The
[previous CEFR four-pass](../cefr-alg-four-pass/SKILL.md) remains an exact-pinned historical frozen package and its existing native attempt-before-reveal policy is unchanged. Do not rewrite its vendored files or apply the single-response Oracle exception inside its live gated session. An article may include a printable same-page oracle without claiming its controlled CEFR practice has run.

## Source, truth and handoff

The original user-supplied v4.0 specification is the **task source**; the linked Medium example is a style pointer and is not executable authority. Read exact LeetCode problem constraints, Python semantics and available code before asserting invariants, asymptotics or result. Keep `MENTAL_TRACE` separate from a genuinely executed `RUNTIME_TESTED`, and `ACTIVE_RECALL_EXERCISE_PROVIDED` separate from observed learner reconstruction or mastery.

New English learning follows [alg-four](../alg-four/SKILL.md), which covers every article decision and core runtime, selects Passive/Active roles and owns acquisition prompts. [cefr-alg-four-pass](../cefr-alg-four-pass/SKILL.md) remains pinned legacy only.

For **complete-article profile** delivery, hand over both approved complete English and Traditional Chinese content, the real sloptrim/semantic review status, reference code, claims/limits and figure specifications to [medium-writing](../medium-writing/SKILL.md). That formatter preserves the existing article compiler Stage 0–7 or supported revision path and optional site/provider readback. Other writing routes retain their current English/sloptrim/translation ownership. This Skill does not create a new stage, change admitted bytes, or claim publication. The English invariant and interview pack are content inside the source-grounded draft/final, not evidence that these steps have run.

## Response outcome

Produce a complete, self-contained explanation in the [v4 contract order](references/v4-contract.md) for ordinary teaching, or one coherent, complete article in the [article-content profile](references/article-content-profile.md) when that profile is selected, with one traceable failure and one valuable changed constraint. A correctness argument is only valid under its listed contract/assumptions. Ensure readers can reconstruct the **why** behind each data structure and operation; reject decorative vocabulary paragraphs that do not affect a decision or runtime behavior. When no real learner attempt is observed, report learning state as unverified.
