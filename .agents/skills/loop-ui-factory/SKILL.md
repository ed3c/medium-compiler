# Loop UI Factory (design only)

1. Read \`docs/loop-studio-design-contract.md\`, \`contracts/loop-ui-artifact-v1.schema.json\` and the original Loop v2 graph/public snapshot rules before a design change. The snapshot, original owner, and access scope are authoritative; the picture is not.
2. Select **one primary design skill** for the present task, then additional skills only for an observed gap:
   - **Anatomy**: create an interactive isometric *explanation* of a selected mechanism. Geometry must derive from source-bound structures; a moving gear must never imply an Agent task executed.
   - **Impeccable**: operate/read product UI critique, accessibility, hierarchy, typography and browser design review. Default for the review workbench.
   - **emil-design-eng / animate / review-animations / animation-performance**: motion timing, focus, reduced motion and animation audits; motion must not invent progression.
   - **design-taste-frontend**: public landing or storytelling pages, **not** task consoles or dashboards.
   - Existing **build-review-interface**: human labeling and trace annotation. An annotation is not verification unless the independent original evaluator accepted it.
3. The four external sources are pinned in \`docs/loop-design-skill-lock.json\`. Project-local installer: \`python3 scripts/install_loop_design_skills.py --plan\`, followed by \`--install\` on an authorized host with Git access. **Installation does not mean the Session loaded a skill**. Check its actual native resolver/readback first. Do not execute bundled third-party binaries or scripts before separate trust review.
4. Generate a \`LoopUIArtifactV1\` with input bindings, design decisions, source-based view states and verification outcomes. Output is an inert reviewed artifact, not an executable \`next\`.
5. TanStack Start owns routing and UI islands, not task state. Existing producer and graph/layout validators remain canonical. Reuse the original data projector rather than reimplementing causal truth in React.
6. Run Test Manager selected controls and browser checks for desktop/mobile, keyboard, reduced motion, source change, inaccessible content, failed handoff, UNKNOWN status and snapshot drift. Report observed vs NOT_RUN. Public deploy remains with its existing owner; no auto-deployment or runtime effects follow from design PASS.
7. NeoWeaver Harness² and RL episode panels are reserved adapters described in the design contract. No current UI status means Trainer, reward, rollout, benchmark, or frozen Codex transfer has executed.

Deliver: source-bound view artifact, selected skill/install/native-consumption receipts, screenshots/browser results when actually run, unchanged runtime readback, and explicit publication decision.
