# Verify instruction behavior

## Sub-features

Freeze conditions; observe a fresh consumer; submit bound evidence; consume the existing owner response.

## How to get to it (user POV)

Select the saved skill and affected decision. Read Soodles review-writing at the selected ref.

## Driving it with native consumers and the public CLI

Freeze protocol and criteria before launch. Give a fresh consumer only its task, instructions and raw evidence. Preserve its actual structured report and available final response. Run the selected checkout's `./soodles schema pclass-feedback` with the saved selection and digest. For `supply_behavior_evidence`, use `next.input.selection` and `next.input.requests` unchanged as the draft and identity source. Preserve owner-selected observations; append only actual requested reports and captures, then save and hash the draft. Match the instruction map exactly; method files are separate. Treat the operation name as a decision label, not a command. Record stdout, stderr, exit and time. Read validity before behavior and follow the returned next operation. Inspect a missing-observation control; it must not be treated as a behavior verdict.

## Gotchas

Consumer reports are not independent all-effects capture. Schema-1 feedback does not certify condition review; record the supervisor's criteria reasoning separately. An admitted writer requires schema 2 and stage-outcome. Missing evidence stays incomplete.
