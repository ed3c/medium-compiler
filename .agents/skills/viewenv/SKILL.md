# ViewEnv Route Skill

## Activation
Only for explicit Environment Design, agent-harness visualization,
RL episode inspection, task-to-environment authoring or visual review.
For unrelated writing and runtime bug fixes do not invoke ViewEnv.
Read the selected Source at its actual commit, the local
`docs/viewenv-route-contract.md`, and
`docs/loop-workbench-tanstack-start.md` before interpreting it.

## Goal / Measurement / Effort / First Causal Breakpoint
Use Soodles Thinking Router V2 by default. Only escalate to V3 if a
second structure/topology representation uncovers a falsifiable premise
that changes an Owner, Verification or required product behavior.
Keep the original Goal, source IDs and Owner next unchanged. Once no
user choice remains, do not ask a new question or reroute an existing task.
A narrower implementation Slice never erases the Parent Goal.

## Five concerns and native routes (skills are not effect authorities)
- **Taste** `taste-skill`: primary for human-facing public story/hero.
  Input public disclosure-approved source and editorial intent.
  Output versioned layout/art direction. Not for an operational dashboard.
- **Anatomy** `anatomy`: primary for isometric, mechanistic explanations.
  Input exact unique Owner Object/Port, original node/edge refs, selected
  source and geometry concept. Output stable SVG/React mechanism and
  Geometry Audit. Animation never establishes a real event or reward.
- **Impeccable** `impeccable`: primary for operational dashboards.
  Input UI goals, states, strict public/private evidence boundary and
  representative source. Output product UX, accessibility/readability
  review and a fixed design system. Its optional launcher is executable
  and needs independent local trust/source review.
- **Emil** `emil-design-eng`, `review-animations`,
  `animation-performance`: primary for motion critique or selected
  supplementary task. Input confirmed state transition and user
  interaction intent. Output motion rules, reduced-motion and performance
  checks. Do not use animation to fabricate progress.
- **Existing** `build-review-interface`: annotation/feedback collection.
  A label is NOT a verified result until the independent original Oracle
  consumes it.

For any one output select **one primary skill** and only necessary
independent secondary reviews. Load the actually installed native SKILL
file and record tool/load evidence separately. A repository lock and
CI installation alone do not prove the Session invoked that skill.

## Environment and Harness² interaction contract
1. Original Soodles/NeoWeaver Owner supplies immutable
   TaskSnapshot/Source, FailureScope, Action allowlist and protected Oracle.
2. `viewenv` Design Compiler consumes the source bytes and explicit
   scene goal -> creates an inert content-bound Design Artifact
   (`scripts/viewenv_design.py`), no new Task or Solver authority.
3. NeoWeaver shared ViewEnvEpisode uses original `parse_proposal`,
   three allowed surfaces (`skill_instruction`, `context_policy`,
   `mcp_wrapper`), rejects foreign or protected refs; framework adapters
   own only transport: OpenEnv (MCP/Step/State) then Verifiers
   (in-process rubric). ORS and NeMo Gym are future adapters of same
   Domain Core, not four copies of task semantics.
4. Harness² candidate **Propose** is NOT environment tool action.
   **Probe** uses Soodles/Noodle authorized existing native Runner and
   fixed frozen Solver, not Harness² unrestricted default sandbox.
   **Compose/Reflect** consume independently reviewed original results;
   no model weight training and no automatic promotion.
5. Model-facing Environment actions produce observations, not Oracle.
   Only original independent Verifier can issue accepted terminal
   reward. Missing reward is null + UNKNOWN, never numeric zero.
6. ViewEnv UI reads versioned/public-approved data only. Three layers:
   Actual (observed), Proposed (hypothesis), Replay (recorded history).
   The UI cannot infer edges from proximity, animation or labels, and
   cannot call a private Host from public TanStack Start routes.
7. Private Design UI may construct an experiment request, but an actual
   request to execute must first pass existing Owner Admission and all
   original auth/Oracle controls. Do not add a generic POST or tool
   launcher in the public frontend.

## Distinct result statuses
Design artifact CREATED does not mean Skills INSTALLED or INVOKED.
Original H0/H0 verifies transport only; H0/H1 with matched conditions
and independent Oracle is separately required for Harness benefit.
Test/Schema PASS, UI screenshot, CI Build, User Review, native execution
and provider landing are separate original outcomes.

## Native usage
Local `python3 scripts/viewenv_design.py --request FILE` emits only the
source-bound design plan; it does not create or alter external effects.
Use the original Test Manager for source change controls, fresh browser
inspection for visuals, and independent Native/Replay verification
before any performance or training claim. Stop only the operation
with missing source, authorization or reward, preserving all others.

## Q32–Q33: factual judgment/tool boundary

The native Soodles `soodles_loop_review_inspect` is **read-only**:
it uses the existing original Host Review Selection and current Owner
readback without writing a new assessment, publishing or running a Worker.
The MCP tool's `readOnlyHint` must be true; the separate
`soodles_loop_review_feedback` tool remains an effectful, source-bound
Session submission with original `session_submitted/unverified` semantics.
Their registrations, invocations, semantic classification, actual P-class
consumption and provider effect are separate evidence claims.

Noodle's source-rail `intent_selection` is **not a completed Session
engineering decision**. `loop_owner_readback` and `schema_feedback`
are producer readbacks, not Session decision outcomes. A
`harness_review` artifact is an original Session-submitted assessment,
but is still semantically `UNVERIFIED`. Treat its absence or stale
content as UNKNOWN, not a missing Tool Call, and never add a green
Edge to repair a visual gap. The original Soodles review owner must
verify any change to original CLI routing. Only source-proven
first causal failures warrant new deterministic CLI behavior.

When source is vendor-pinned, refresh the original Noodle version and
the Git blob manifest together, test actual React/DOM Browser and
preserve Source/Runtime separation. These are not real Agent-compliance
Evals or production Cloud promotion.
