# ChatGPT cloud-native writer/reader route

Use only for an already authorized ChatGPT cloud task. Repository work uses GitHub and
existing Actions; independent model work uses the actual exposed native subagent schema.
Python article helpers are deterministic writing tools, not the Local Codex agent launcher.
No Codex CLI, API key, copied login, VM or replacement model adapter is required by this route.

## Read the selected task, not a new platform plan

Read the current Issue/PR/head through GitHub. Preserve its episode, source versions,
owner decisions and next operation. The current pending Ops episode is not ACCEPTED.
Use the existing task/source allowlist as input provenance, not the full repository history,
later answer-bearing article additions, observer code or the other arm's output.
The retained experiment.json selects `host_codex_exec`; it is NOT a native launch contract.
Do not feed its local host approval or Codex event format into native execution.

## Native launch and observation

Observe this Session's actual native capability. Unknown exposure permits scoped discovery;
confirmed absence stops native launch only. Keep the route and continue authorized GitHub
work. A fresh Session refreshes exposure; an unchanged turn does not repeat discovery.

When a native action is exposed and authorized, use its current schema directly. For a
consumer use no inherited conversation (`fork_turns: "none"` where the schema supports it).
Send only its task, pinned instruction/code refs and required inputs. Keep expected outcomes
with the supervisor. Native threads may share files: use distinct evidence directories,
pinned read-only GitHub inputs and verify actual visibility before claiming isolation.

Before scored writer runs, perform one uncounted capture pilot. Its bounded task is to read
`evals/writing/ops-evidence-handoff/task.md` from medium-compiler at
`bea94040e9a4d2c7e99356a4fe31a6a7723c4124` via GitHub and report actual source/access/content.
Do not supply expected content or ask it to solve the writing task. Preserve the actual
spawn call/result, child identity and wait/completion result. Check whether the supervising
observer can independently read raw child tool requests/results and delivered input identity.
A child report is self-report; a successful launch is not proof of full capture or freshness.
If capture is unavailable, preserve the pilot and report the precise limitation. Do not
resample, emulate raw events or switch to Codex/API transport to obtain a green result.

## Comparison and continuation

Before any scored native run, freeze its actual caller/model/tools/input delivery/observer
and exposure, retaining the selected baseline `71fce847` and treatment `df138896` writing
files and common task/source bytes where they can be delivered equivalently. Keep the
three-per-arm budget and interleaving B/T/T/B/B/T separate from the uncounted pilot.
A carrier change is recorded before results, never silently relabeled as the local study.
If equivalent inputs or independent capture cannot be established, the comparison waits;
repository changes, source analysis and mechanical Actions do not wait for it.

Review every actual native event using the preselected criteria. A prevented wrong attempt
still counts; unknown/missing observations are not zeros. Keep semantic labels independent.
No fake Codex JSONL or author-only review can supply independent native telemetry.
A true accepted-learning positive path needs the actual upstream handoff. An isolated reader
gets only the article/audience/questions and must quote article evidence. Do not substitute
a coordinator reread for a fresh reader or independent pstack source-review wave.
