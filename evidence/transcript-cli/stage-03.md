## 驗證值得多少成本，要放回同一件工作比較

建立上述流程需要時間。每次都執行所有檢查，也可能讓一個簡單修改變成昂貴工作。增加功能之前，應該先比較兩條可以實際使用的路徑。

**直接使用通用 Agent，再由人驗收。** 對低頻、容易看懂、出錯後能快速復原的任務，這可能已經足夠。工程師保留全局理解，工具也比較少。代價是每次都要重新確認成果與限制。

**把反覆發生的驗收問題固化到產品。** 如果使用者經常漏查語系、混淆預覽版本，或誤用先前的通過結果，可以增加版本綁定與必要檢查。代價是維護資料結構、判斷檢查失效，以及處理無法自動判定的情況。

選擇條件不是 Agent 的數量，而是第二條路徑省下的人工與返工，能否超過新增的執行和維護成本。沒有真實重複問題之前，先建立完整的協調平台，可能只是把未知成本提前引進來。

成本可以從一次完整的工作期間計算。設這段期間總共嘗試 N 件工作，其中 A 件最後通過約定驗收；所有嘗試消耗的推理費、工具費、驗證費、人工時間成本與返工成本合計為 C。當 A 大於零時，每件通過驗收的工作成本就是 C / A。失敗嘗試的費用也留在 C 裡，否則會高估效率。

這裡沒有假設任何實測數字。要比較兩種方案，還需要使用相近的任務組成與相同驗收標準，另外觀察耗時、人工介入與交付後才發現的錯誤。若 A 為零，就沒有可報告的成功交付單位成本；也不能透過降低驗收標準，製造成本下降的假象。

對商品頁案例而言，一次視覺檢查是否值得重跑，取決於它能排除的具體風險。可靠的依賴關係可以減少不必要的檢查；未知的影響範圍則需要額外觀察。省略測試本身，不構成效率改善的證據。
